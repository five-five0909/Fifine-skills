# 命名语法与合规判据

> 本文件与 `scripts/naming_lib.py` 一一对应。改代码必须同步改这里，反之亦然。

## 1. 正则（与代码同源）

```python
TAGS = "草稿|待审|待改|定稿|归档"                                    # 封闭集合，恰好两个汉字
SEG  = r"[0-9A-Za-z一-鿿][0-9A-Za-z一-鿿 ]{0,39}"                  # 单个关键词，最长 40
CORE_FILE = SEG + r"(?:-" + SEG + r"){1,4}"                        # 文件：2~5 个关键词
CORE_DIR  = SEG + r"(?:-" + SEG + r"){0,4}"                        # 目录：1~5 个关键词
VER  = r"V[1-9]\d*(?:\.\d{1,2}){0,2}"                              # V1 / V2 / V1.1 / V1.10
EXT  = r"\.[0-9A-Za-z]{1,8}|\.tar\.(?:gz|bz2|xz|zst)"              # 单个后缀，或已知复合后缀

FILE_RE = ^(?:【TAGS】)?(?P<date>\d{8})_(?P<core>CORE_FILE)(?:_(?P<ver>VER))?
          (?P<ext>EXT)?$
DIR_RE  = ^(?:(?P<date>\d{8})_)?(?P<core>CORE_DIR)$
```

`一-鿿` 即 `\u4e00-\u9fff`（CJK 基本区）。`SEG` 有意不含 `-` `_` `.` `【` `】`，把它们留给语法位。

## 2. 分隔符契约

| 记号 | 语义 | 位置 | 违规后果 |
|---|---|---|---|
| `】`+数字 | 标签与日期**紧邻**，不加任何分隔符 | `【定稿】20260918_` | 多插 `_` 或空格 → 正则不匹配 |
| `_` | 字段分隔符，**保留字符** | 日期/核心/版本之间 | 核心信息内出现 `_` → 判为不合规 |
| `-` | 核心信息内部关键词分隔，**两侧紧贴** | `秋季活动-报价单` | 连续 `--`、首尾 `-`、或 `Q3 - 预算` 这种留空格 → 不合规 |
| 空格 | 单个关键词内部（英文词之间） | `Q3 Sales-Report` | 连续空格 → 警告 |
| `.` | 扩展名与版本号小数点 | `_V1.1.docx` | 核心信息内出现 `.` → 不合规 |

## 3. 正则之外的判据

`validate()` 在正则命中后继续检查；任一条失败即 `NON_CANONICAL`。

| 判据 | 阈值 | 失败/提示 |
|---|---|---|
| 日期可解析 | `strptime("%Y%m%d")` | `20261332` → 不是真实日历日 |
| 日期不过分未来 | ≤ 今天 + 366 天 | 疑似笔误 |
| 关键词数量 | 文件 2~5，目录 1~5 | 单关键词 `报价` 直接不合规 |
| 单关键词长度 | ≤ 40 字符 | 超限报错 |
| 主名长度 | ≤ 100 字符 | 超限报错 |
| 单段字节数 | ≤ 200 字节（UTF-8） | 中文每字约 3 字节，字符数够也可能超 |
| 完整路径 | ≤ 240 字符 | Windows 260 余量 |
| Windows 非法字符 | `< > : " / \ | ? *` + 控制字符 | 硬拒绝 |
| 核心信息内的点号 | 单个关键词不得含 `.` | 硬拒绝，诊断为「版本号请写成 `_V`」 |
| 扩展名形态 | 一个点号段，或 `.tar.gz` 这类白名单复合后缀 | 硬拒绝 |
| Windows 保留设备名 | `CON PRN AUX NUL COM1-9 LPT1-9` | 硬拒绝 |
| 结尾 | 不得以 `.` 或空格结尾 | 硬拒绝 |
| `.` / `..` | 不可作为名字 | 硬拒绝 |
| NFC | `normalize("NFC", name) == name` | 警告（同步盘可能生成重名副本） |
| shell 不友好字符 | `& % # ( ) [ ] { } ; , @ $ \` ^ ~ = ! ' +` | 警告，建议改写 |
| 标签合法性 | `【x】` 的 x 必须落在封闭集合 | 「待定」等 → 不合规并给出替换建议 |
| 目录附加规则 | 目录不得含 `【】`、不得含 `_V` | 硬拒绝 |
| 无扩展名 | — | 警告，需人工确认 |

## 4. 警告与错误的分界

只有以下情形降级为**警告**（`COMPLIANT` 仍成立，不阻塞执行）：

- `collab` 模式下文件缺状态标签（建议补，不强制）。反方向不提示：`solo` 模式下带 `【草稿】` 这类标签**静默接受**——标签永远不会造成损害，而每个 solo 文件都冒一条提示只会淹掉真正的问题；
- 可编辑交付物（`.doc .docx .xls .xlsx .ppt .pptx .md .pdf .key .pages .numbers .psd .ai .sketch .wps`）缺 `_V`；若核心信息末尾粘着一个整数版本号（`…-V1.docx`），改为提示把它改写成放在扩展名前的 `_V1`——带小数的 `-V1.2` 写法已经是硬错误（见第 3 节）；
- shell 不友好字符、NFC、多余空格；
- 无扩展名。

## 5. 状态取值

| status | 含义 | 执行器行为 |
|---|---|---|
| `COMPLIANT` | 已合规（可能带警告） | 无需改动 |
| `NON_CANONICAL` | 违反至少一条硬判据 | 需要新目标名 |
| `SKIP-EXCLUDED` | 点号开头名、`.DS_Store`、`Thumbs.db`、`desktop.ini`、`ntuser.dat` | 不参与整理 |
| `locked: true` | 标签为 `定稿` 或 `归档` | 改动主名的请求被拒绝 |

遍历目录时另外排除：`.git .hg .svn .agents .claude .codex .trellis .vscode node_modules __pycache__ .venv venv .cache .paddlex dist build .pytest_cache .idea`，以及符号链接。

## 6. 幂等判定

重复运行不应产生改动：

- 体检：`FILE_RE`/`DIR_RE` 命中 + 判据全过 → `COMPLIANT`，不生成建议；
- 执行：`old_path` 与目标 `dst` 相同 → `SKIP-SAME`（计入 pre-flight reject，不计入改动数）；
- 建议名在输出前会**自我校验**一次，通不过就返回空建议，避免审计器吐出自己都不认的名字。

## 7. 旧名回收：`salvage()` 与 `hints`

对不合规的旧名，脚本按以下顺序尽量复用信息，而不是丢掉重写：

1. `【x】` 前缀：只有 x 属于封闭集合时才保留为标签；「待定」这类被丢弃，其字面值降级为候选关键词；
2. 末尾重复计数：`(1)`、`（2）` 这类浏览器/IM 的重复下载计数先剥掉——否则末尾锚定的版本号正则会被 `v3(1)` 挡住；
3. 末尾版本号：`_V1.2`、`-v3`、` v2` → 规范成 `V1.2 / V3 / V2`（尾部长度 ≤8 才认，避免吃掉正文）；
4. 日期：`20260910`、`2026-09-10`、`2026.09.10`、`2026_09_10` 任意形式，经 `parse_date` 验证后取用；
5. 剩余片段切成候选关键词：先剥掉**粘连在中文内容尾部**的噪声词（`最终版`、`副本`、`修改版`、`copy`、`draft` 等）与末尾 `vN`，循环到不再变化，因此 `会议纪要最终版v3` → `会议纪要`；整词命中噪声表或纯数字（日期、时间、计数）的片段直接丢弃。

`audit_names.py` 附带的 `hints` 字段：`mtime_date`、`ancestor_date`（上级目录的日期前缀）、`project_from_dir`（上级目录的第一个关键词，跳过 `交付物` 这类角色目录）、`keyword_candidates`、`ext`、`depth`。

建议名的日期优先级：**名字里已写的日期 > 上级目录日期 > 文件 mtime**。人手写在目录名里的日期能挺过复制，mtime 挺不过。

## 8. 扩展名与复合后缀

只允许**一个**点号段（`.docx`、`.xlsx`），外加四个已知复合后缀整体保留：`.tar.gz`、`.tar.bz2`、`.tar.xz`、`.tar.zst`。

早期版本写成通用的「一到两个点号段」，于是 `20260910_项目-需求-V1.2.pptx` 被解析成核心信息 `项目-需求-V1` + 扩展名 `.2.pptx`，**判为合规**——版本号里的那个点被扩展名吞掉了，而 SKILL.md 的反例表明确说这个写法要改。所以通用重复段被换成显式白名单。

代价：`report.en.docx`、`数据.csv.bak` 这类多点命名现在判为不合规。处理方式是限定词进关键词（`20260910_项目-报告-EN.docx`），而不是让语法位暧昧。`a.b.c.d` 这种四段名同样拒绝，需人工确认。
