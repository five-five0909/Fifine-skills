# 跨平台安全与同步盘禁忌

> 本文件与 `scripts/naming_lib.py` 的 `_check_common()` / `validate()` 一一对应。
> 结论先行：这套命名法**默认可以在 Windows / macOS / Linux 之间自由往返**，代价是放弃了几个看起来很方便的字符。

## 1. 三层长度预算

单看字符数不够：多数文件系统对**单个路径段**的限制是 255 **字节**，一个汉字占 3 字节，所以 90 个汉字的中文主名合法但写不下去（`File name too long`）。`naming_lib.py` 因此同时卡三道：

| 预算 | 常量 | 判据 | 超了会怎样 |
|---|---|---|---|
| 主名 ≤ 100 字符 | `MAX_STEM` | `len(stem)` | 报错，建议砍关键词 |
| 单段 ≤ 200 字节 | `MAX_NAME_BYTES` | `len(nfc(name).encode("utf-8"))` | 报错，中名安全线 |
| 关键词 ≤ 40 字符 | `MAX_KEYWORD` | 单个 `-` 分段长度 | 报错，关键词不是长句 |
| 完整路径 ≤ 240 字符 | `MAX_FULL_PATH` | `len(os.path.join(dir_path, name))` | 报错，给 Windows 260 留余量 |

`MAX_FULL_PATH` 只在传了 `dir_path` 时才检查——体检时会带上真实父目录，所以深层目录里的长名会被提前拦下。

**为什么是 240 而不是 260**：Windows 传统 `MAX_PATH` 为 260，且 UNC 路径、8.3 短名、加密/同步临时文件都会再吃掉一截。留 20 字符比留 0 字符便宜。

## 2. 硬拒绝字符（`ILLEGAL_CHARS`）

```
< > : " / \ | ? *  以及所有 \x00-\x1f 控制字符
```

任一命中即 `INVALID_NAME`，执行器不会写入。旧名里常见的是冒号：`Q3:预算.xlsx` → 改成 `20260910_Q3-预算.xlsx`。

**别把冒号换成 ` -`**（`Q3 - 预算`）——关键词必须以字母/数字/汉字起头，` - 预算` 的前导空格会被语法拒绝。中划线两侧永远紧贴关键词，不留空格。反斜杠与正斜杠是路径分隔符，不是「可选字符」——它们在任何平台上都不可能出现。

## 3. Windows 保留设备名（`RESERVED_NAME`）

```
CON PRN AUX NUL COM1-COM9 LPT1-LPT9
```

大小写不敏感，**且带扩展名也照样命中**：`CON.docx`、`nul.tar.gz` 在 Windows 上无法创建，在 Linux/macOS 上却能建——这是典型的「在同事机器上突然打不开」。判据用 `^(...)(\..*)?$`，所以整段名字（含后缀）都会检查。

现实里最容易踩的是 `NUL`（有人把空占位文件命名成 `nul.txt`）和 `COM1`（串口调试日志）。

## 4. 结尾规则

名称不得以 `.` 或空格结尾：Windows 会静默剥掉它们，于是 `报告.` 在同事机器上变成 `报告`，脚本随后认为目标不存在。`.` 与 `..` 直接拒绝。

## 5. NFC 规范化

`validate()` 检查 `unicodedata.normalize("NFC", name) == name`，不等则**警告**。

原因：macOS（HFS+/APFS）历史上会把文件名按 NFD 存储，而 Windows/Linux 用 NFC。同一个「张明.pdf」在两台机器上可能是两个不同的字节串，同步盘会把它当作两个文件各留一份，产生 `conflicted copy`。中文里受影响的主要是带兼容分解形式的字符与假名浊点，出现概率低但排查成本高，所以做成警告而不是拒绝。

顺带一提：`nfc()` 只用于**判断与字节计数**，不会静默改写用户已有的文件名——重写非 NFC 名是一次内容变更，必须走确认门。

## 6. shell 不友好字符（`SHELL_HOSTILE`）

```
& % # ( ) [ ] { } ; , @ $ ` ^ ~ = ! ' +
```

这些字符在三个平台上都**合法**，只警告不拒绝。风险来自工具链：

- `(1)`、`[副本]`、`最终版 (2).docx`：`glob` / `*` 匹配会把它们当成字符类，`cp a(1).docx b` 直接语法报错。用户说「搜一下带 2 的那份」时，`(2)` 会干扰 `grep`/`find`。
- `&` `;` `|`：命令分隔符。
- `$` `` ` `` `!`：变量与历史展开。
- `#`：行首时被当注释。
- `~`：波浪号展开。
- 空格：不是错误，但每个 shell 命令都要加引号。

`【】` **不在**这个集合里——它们是合法 Unicode 标点，不在 Windows 非法字符集中，NTFS / APFS / ext4 均可写入。这是本命名法刻意保留的全角括号：视觉上比 `[draft]` 显眼，且不落在 ASCII 语法位上，不会和 `()` 的 shell 语义冲突。

## 7. `【】` 的已知残余风险

个别同步与上传通道对全角标点的处理不一致（老版本 WebDAV、某些网盘的分享链接编码、把文件名当 URL path 直接拼接的脚本）。因此：

> 首次在同步盘目录上批量执行前，先整理 **1~2 个文件**，等同步完成，在另一台机器上确认能正常打开，再跑完整 plan。

若验证失败，降级方案是丢掉标签（保留日期+核心+版本），标签信息移入目录层（`待审/` 子目录），**不要**把 `【】` 替换成半角 `[ ]`——那会撞上 `SHELL_HOSTILE`。

## 8. 大小写不敏感冲突

Windows 与默认配置的 macOS 文件系统不区分大小写。执行器用 `os.path.basename(path).casefold()` 作为槽位键（`apply_naming.py` 的 `slot()`），于是 `Report_V1.docx` 与 `report_v1.docx` 判为同一位置 → `CONFLICT`。

Linux（ext4，区分大小写）上这是两个不同文件，因此这条检查是**向下兼容**的：在 Linux 上多拒一次，代价是让用户改核心信息；在 Windows 上漏拒一次，代价是静默覆盖。所以宁可多拒。

**绝不自动加后缀**（`_1`、` (2)`）。自动加后缀会把冲突藏起来，并在目录里留下用户从没确认过的名字。冲突必须回到方案表里由人决定。

## 9. 遍历时的排除集

`audit_names.py` 不下探、不改名：

- 目录：`EXCLUDED_DIRS` = `.git .hg .svn .agents .claude .codex .trellis .vscode node_modules __pycache__ .venv venv .cache .paddlex dist build .pytest_cache .idea`
- 文件：任何点号开头的名字（`.env`、`.gitignore`、`.DS_Store`）以及 `Thumbs.db`、`desktop.ini`、`ntuser.dat` → `SKIP-EXCLUDED`
- 符号链接：跳过。跟随链接改名会在目录树之外留下悬空引用。

这些名字靠**精确名字**被程序读取，改名等于删除。

## 10. 落盘细节

- 移动用 `shutil.move`，跨设备时它会退化为「复制 + 删除」；执行器捕获异常并记 `ERROR`，不重试。
- 改名环（A↔B 互换）经 `.naming-tmp<N><ext>` 两阶段中转，日志里那条标 `intermediate: true`。
- 目标目录不存在时会被创建（`prepare_dirs()` 用 `os.makedirs`），但**只创建 plan 里真正需要的**，并把新建的层级按 top→leaf 记入 `created_dirs`；`--undo` 时反向 `os.rmdir`，非空则保留并说明——绝不 `rmtree`。`--dry-run` 只登记不创建。
- 创建后仍不是目录（权限、竞态）→ 该条记 `ERROR 目标目录不存在`，跳过而不猜测位置。
